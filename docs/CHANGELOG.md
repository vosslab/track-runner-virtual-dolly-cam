### Decisions and Failures

- Solve-queue refactor -- `solve_queue` is intentionally a domain-specific name, not a generic `queue_manager` or `interval_dispatch` abstraction. The module IS solver interval orchestration -- making that honest in the filename discourages future feature creep into a general-purpose queue layer that this codebase does not need.
- Solve-queue refactor -- [track_runner/interval_fingerprint.py](../track_runner/interval_fingerprint.py) is locked to fingerprint + seed-filter only. A future patch that adds `race_phase`, `erasure`, or other "intrinsic-to-an-interval" helpers to this module is a regression -- a catch-all low-level module is how premature abstraction starts. New helpers belong in their own file or stay in `interval_solver.py` until a concrete third caller exists.
- Solve-queue refactor -- `ExecutionContext` holds immutable run configuration only (reader, transforms, fps, paths, worker count, debug). No accumulators, no progress-bar handles, no mutable state. Future features that need a shared mutable must pass it explicitly as a kwarg; smuggling state through the context is rejected at review.
- Solve-queue refactor -- the function-level import of `solve_interval_analytical` inside `execute_interval_work` is a tactical compromise, not an endpoint. The clean ownership story is "queue owns execution AND solve implementation lives in a module the queue imports at module load." Moving `solve_interval_analytical` is out of scope for this refactor; the comment at the import site documents it as such. Do not propagate the pattern to new symbols.
- Solve-queue refactor -- fingerprint drift between solve and refine modes was the primary risk this refactor mitigates. Before: two independent fingerprint walks had to agree; adding a queue invariant required editing two files and proving they still agreed. After: `plan_interval_work` is the single source of truth, and `test_fingerprints_unchanged_by_parallel_refactor` in [tests/test_solver_parallelism.py](../tests/test_solver_parallelism.py) locks the bytes.
- The empty-track hover bug visible in the user's reference frame (FWD, fused, and BWD torso boxes over an empty curve while the real runners were ~100 px to the right) was diagnosed as solver drift, not a fusion gap. The purely-kinematic analytical propagator consulted no image evidence; seeds 100 px left of truth were interpolated to more of the same. The previous fix (motion-cue fusion as a post-process) addressed the symptom by snapping to blobs globally, but its cross-frame memory (`prev_accepted_blob`, `miss_count`, temporal chains) re-introduced drift through the back door and made refine O(total frames). This patch series moves correction into the propagator itself as a stateless, local, three-outcome operation (blend, ignore, fall through), keeps the local temporal window bounded to `{t-1, t, t+1}` computed from `raw_pred` only, and deletes the chained code so it cannot regress. Design philosophy and invariant list live at the top of `~/.claude/plans/happy-forging-valiant.md`.
- Post-audit, five corrections were applied to the initial blob-snap landing. (1) Temporal-smoothness gate: the original spec `dist(blob, raw[t-1] + v_prev) < beta * |v_prev|` algebraically collapsed to `dist(blob, raw[t]) < beta * |v_prev|` (velocity-scaled proximity), not a true motion-path check. Replaced with `_motion_path_ok()` in [track_runner/velocity_model.py](../track_runner/velocity_model.py): decomposes `blob - anchor` into along-motion and perpendicular components and rejects blobs that sit off the motion line (perpendicular > `PATH_PERP_FRACTION * |v|`) OR outside the forward segment (`proj` not in `[0, |v| * (1 + PATH_SLACK)]`). Both neighbors (raw[i-1] with `v_prev` and raw[i+1] with `-v_next`) must pass when their motion magnitudes exceed the velocity floor. (2) Removed the dead blob-coverage severity tie-breaker from [track_runner/review.py](../track_runner/review.py): `severity == "low"` required `agreement >= 0.40` while the tie-breaker guard required `agreement < 0.30`, so the rule never fired. Coverage remains a pure diagnostic. (3) Split the aggregated `blob_coverage_fraction` into per-pass `blob_coverage_fwd` and `blob_coverage_bwd` in [track_runner/interval_solver.py](../track_runner/interval_solver.py) `_coverage_from_track` and `_stamp_blob_coverage`; aggregation hid FWD/BWD asymmetry which is exactly the signal the dual-scoring design wants preserved. (4) Added explicit documentation to `observe_blob_at` noting the ROI-coupling caveat (first caller at a frame sets the ROI; second caller reuses). (5) Renamed destructured locals inside `_apply_blob_snap` to `raw_cx` / `raw_cy` and introduced separate `snap_cx` / `snap_cy` output locals so the read path (gates) and write path (blend) are typographically distinct. New invariant test `test_raw_pred_is_never_mutated_by_snap` locks the separation. Constants in the solver fingerprint bumped accordingly (`BLOB_SNAP_BETA` -> `BLOB_SNAP_PATH_SLACK` + `BLOB_SNAP_PATH_PERP_FRACTION`).
- Triple-audit round surfaced a HIGH-severity spec deviation and two philosophy refinements. (HIGH) WP-B1 specified `Cache key is a stable tuple of (frame_index, roi_hash)`, but the initial implementation keyed by `frame_index` alone. This silently constrained BWD's candidate blob pool to the ROI FWD picked -- precisely the coupling the dual-scoring philosophy forbids. Restructured `observe_blob_at` in [track_runner/residual_motion.py](../track_runner/residual_motion.py) to key the cache by `(frame_index, roi)` where `roi` is the ROI tuple itself; the `_frames` sub-cache stays keyed by `frame_index` alone (raw frame bytes are ROI-independent). FWD and BWD with divergent raw_pred now each compute their own residual on the cache-miss path; convergent cases still share one computation. On tight curves and crowd scenes -- the exact regimes this feature targets -- FWD/BWD independence is now structural, not empirical. (Refinement 1) Motion-path gate made asymmetric in [track_runner/velocity_model.py](../track_runner/velocity_model.py) `_apply_blob_snap`: only `path_ok_prev` is checked. The former symmetric `prev AND next` rule over-rejected valid blobs near upcoming-occlusion edges and curvature where t+1 raw_pred carries accumulated Hermite error. Iteration-order "prev" is always closer to the pass's starting seed and has accumulated fewer propagation steps, so it is the more trustworthy anchor; t+1 disagreement is tolerated by construction. `path_ok_next` computation removed entirely so the asymmetry cannot be misread as accidental. (Refinement 2) ROI tuple is quantized to `ROI_QUANT = 8` px in `_compute_roi`: sub-quantum FWD/BWD jitter collapses into the same cache bucket (avoiding accidental cache fragmentation), while tens-of-pixels divergence produces distinct ROIs. New test `test_roi_quantization_collapses_subpixel_jitter` locks this invariant.

- Rewrote scoring in [tools/diagnose_residual_motion.py](../tools/diagnose_residual_motion.py) from box-based metrics to constrained temporal blob tracking. Previous metrics scored motion blobs against the solver's predicted torso box, which is systematically wrong in low-confidence gaps -- conflating motion signal quality with box prediction error. Gate 1 (seed frames) must pass before trusting gate 2 (gap frames). Cross-track distance is the primary geometric penalty; along-track offset is reported but weakly penalized. Key decision: the diagnostic video proved the motion signal is strong and usable, so this is a selection problem, not a detection problem.
- Documented the cross-correlation vs feature detection design decision in [docs/CODE_ARCHITECTURE.md](CODE_ARCHITECTURE.md). All camera motion estimation uses FFT-based phase correlation (`cv2.phaseCorrelate`), not feature detectors (SIFT, ORB, etc.). Track surfaces are large uniform regions with few stable keypoints, making correlation-based methods far more reliable. The diagnostic motion tool (`tools/diagnose_residual_motion.py`) also relies on this same phase-correlation pipeline via `SceneTransform`. Added an explicit rule: do not introduce feature-detection-based camera motion without demonstrating it outperforms phase correlation on actual track video.
